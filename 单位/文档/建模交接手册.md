## 2 环境（**最容易翻车的一条**）

| 项 | 本机实测值 | 说明 |
|---|---|---|
| Blender | **5.1.2**（`D:\blender\blender.exe`） | 脚本用了 `action_slots`（Blender 4.4+ 的 layered action API）。**装 4.2 或更低会直接报错** |
| 自带 Python | **3.13**（`__pycache__/…cpython-313.pyc`） | 与 Blender 5.1 匹配 |
| 跑法 | `blender -b --python xxx.py`（**后台模式**） | 所有脚本都 `import bpy` / `mathutils`，**系统 Python 跑不了** |

换机器要改的两处：

1. 所有命令里的 `D:\blender\blender.exe` → 新机器的 Blender 路径。
2. `野怪/run_*.py`、`联盟/run_*.py` 用 `os.path.dirname(__file__)` 定位 `库/`，
   **只要 `单位/` 的目录结构原样保留就不需要改路径**——所以别拆散拷。

自检环境是否装对：

```powershell
& '<新路径>\blender.exe' -b --python 'E:\…\单位\野怪\run_战士.py'
```

跑完应打印 `[done] …豺狼人战士.glb`，且自检十项与 `文档/自检报告.md` §1 的数字**逐位一致**
（3608 面 / 3.65% / loop_Δ=0.0）。数字对不上说明环境不对，先别开工。

## 5 注意事项清单

### 开工前 5 条

1. 确认 Blender 位置。
2. 确认 `单位_v4/产出/` 里的基准 QC 图还在——新单位要跟它们**同机位同三点光**对比。
3. 先定**关节表 `J`**，再定部件表（顺序反了会反复返工）。
4. 量一次臂展/腿长再做动作：联盟臂展 0.63~0.68m、野怪 0.64m。
5. 同种族新兵种：先读 §6，把三个识别点定下来再动几何。

### 收工前 5 条

1. `normalize()` 后打印 `[zmin]` 前四名，**最低件必须是脚趾**（武器垂到地下会把整只顶起来）。
2. `audit.run()` **十项全绿**（+ §6 的两项新指标）。N/A 要写明，不许写 PASS 蒙过去。
3. 出 3 张 QC（front / iso / rts 40°）+ 各动作 6 帧条，与基准图同机位。
4. `dump_table.py` 重生成 `对照表.md`，再 `git commit`。
5. 提交信息：`feat(<阵营>): <单位> <做了什么>`，正文列三条以内的关键数字。

### 九个坑（摘要，全文见 `制作要点与经验.md` §5）

1. 倒角+CC 叠加 → 面数爆炸（战士从 6452 压到 3608）
2. 武器垂地 → 整只被顶离地面、脚底浮空
3. 手臂够不着握点 → 肘外翻、双臂绞成团（双手持械副手握杆尾 `grip2=-0.095`）
4. 白骨横排 → 读成"第二张嘴"（改成斜挎垂挂）
5. 移植部件表时同名 helper 坐标系不同 → 部件飞到半空
6. 归一化顺序错 → 骨架与网格脱钩
7. **自检读 pose 会被上一条动作污染 → 一律读 rest 数据**
8. join 成网格后部件名就没了 → 要在 `bind()` 前把质心记进 `u.meta`
9. 根位移判据是**白名单**（`walk_film/run_film/stagger` 允许有），不是"全 0"

### 引擎侧（另一台机器没有游戏工程时，只做到第 ① 步）

```
① 放文件    美术/模型/<分组>/<名>.glb
② 重导入    godot --headless --path . --import      ← 少了这条运行时报"找不到模型"
③ 登记单位  代码/配置/单位表.gd 加 UnitDef 块        ← 没有这条场上根本不出现
④ 染色键    代码/美术/调色板.gd 补 "tribe"（仅野怪）← 没有这条换色位变灰
```

③ 最小字段照 `footman` 抄：`id / display_name / kind / model_path / anim_set / height /
body_radius / max_hp / armor / attack_damage / attack_cooldown / attack_range / move_speed`。
动作名与骨名**不用登记**（引擎不校验骨名，动作缺失走降级链 `attack→shoot→cast→walk`）。

## 6 ★ 同种族多兵种：差异化规范（本次新增）

### 6.1 诊断：豺狼人身上出了什么问题（只总结，本次不改）

翻 `野怪/gnoll.py` 就能看出根因——**共用体的边界划错了**：

| 共用 | 差异 |
|---|---|
| `J` 关节表（全身） | 身高 1.98 / 1.86 + `slim=0.90` |
| `torso()` `leg()` `head()` `tail()` | 肩饰（骨刺 vs 短鬃） |
| 头/躯干/四肢/尾 **100% 同几何** | 胸口骨串（有 / 无） |
| | 武器（流星锤 vs 匕首） |

结果：**躯干、四肢、头、尾四条剪影完全重合**，全部差异压在"肩 + 武器"两处。
而武器恰恰是看不清的那一处：

- **匕首**：刀刃长 0.24m，宽 0.052 → **末端 0.010m（1cm）**；武器网格仅 156 面。
- **流星锤**：锤头 0.214m 尚可，但链条方向 z 分量 −0.902 → **锤头拖到地面**，
  与腿同高；`iron #4C5058`（灰蓝）与腿的 `fur_dark #3E3328`（暗棕）明度接近 → 糊在腿里。
- **RTS 俯角 40°**：单位在屏幕上约 64px 高时，1px ≈ 3cm。匕首末端 1cm ≈ **0.3 像素**。

所以在游戏实际视角下，两个豺狼人的剪影是「同一只兽人」，而唯一的区分手段（武器）
在屏幕上不足 1 像素。**这不是配色问题，是"识别点数量与分布"的问题。**

### 6.2 三条硬指标（同种族 ≥2 个兵种时必须满足）

#### 指标 A：识别点 ≥ 3 个，且分布在 **3 个不同高度带**

高度带划分：`① 头颈（眼线以上）` `② 躯干/肩（肩线到腰）` `③ 下肢 + 武器`。

**每个兵种必须在 ① ② ③ 里各至少有一个「RTS 视角下可辨」的差异点。**
豺狼人的失败就是：差异只在 ②（肩饰）和 ③（武器），① 头颈完全一样。

"可辨"的判据：把 RTS 图缩到 **96px 高**，该差异点仍能被肉眼指认。

#### 指标 B：武器可视性（直接针对"武器看不清"）

| 项 | 门槛 | 豺狼人实测（对照） |
|---|---|---|
| 武器投影面积 / 全身投影面积（RTS 机位） | **≥ 8%** | 斥候远低于此 |
| 武器主件最小厚度 | **≥ 0.05 m** | 匕首刃末端 0.010 m ✗ |
| 武器最低点离地 z | **≥ 0.15 m**（不许拖地） | 锤头 z≈0.05 ✗ |
| 武器主色 vs 相邻身体件明度差 | **≥ 0.15** | iron #4C5058 vs fur_dark #3E3328 ✗ |

投影面积口径与现有 `audit.tribe_ratio` 一致：**朝镜头面（法线·L>0）的投影面积 / 全身同口径**，
只是把统计对象从 `unit_tribe` 换成 `unit_weapon`，机位换成 `rts`。

> 备注：换色位只有 3~5%（豺狼人实测 3.65%/3.83%），**太小，不能当识别点用**。
> 部落色可以辅助，但不能承担兵种区分。

#### 指标 C：剪影差异 Silhouette Δ ≥ 30%

两个兵种在**同一 RTS 机位**渲染剪影 → 缩到 96×96 → 逐像素比较：

```
Silhouette Δ = 不同像素数 / 两剪影并集像素数    要求 ≥ 30%
```

豺狼人这一项达不到（四个部位 100% 同几何，只有身高差 6%）。

**体型差异不能靠整体缩放**：`slim=0.90` 只收 X/Y，剪影**形状不变**，远看还是同一只。
要拉开体型，必须改**比例**——两兵种的 `肩宽/身高` 或 `腿长/身高` 至少一项差 **≥ 8%**。

### 6.3 差异化从哪些维度切入（按 RTS 有效性排序）

**最有效：竖向道具**（旗杆、长矛、图腾杖、背旗、高耸头饰）
理由：俯角下横向装备只能让轮廓"胖一点"，而竖向道具会**跳出身体轮廓进入背景**，
与背景形成对比，是最强的剪影语言。这也是本项目做 RTS 单位最该优先用的一招。

| 高度带 | 可用手段 |
|---|---|
| ① 头颈 | 耳型（竖/折/长）、吻长吻型、头饰（骨/羽/角/兜帽）、鬃毛形态、面具 |
| ② 躯干肩 | 护肩形态、背鳍/驼峰、背负物（旗/骨架/袋/盾）、胸甲轮廓、斜挎物 |
| ③ 下肢+武器 | 护胫/绑腿、趾爪形态、**武器形态 + 持法**（单手/双手/举高/扛肩） |

**次有效：动作节奏**——同为 idle，一个沉稳一个警觉；walk 的步幅/摆臂幅度拉开。
这个不增加面数，但只在单位动起来时有用，不能替代几何差异。

**最弱：配色**——占比太小（换色位 3~5%），且 RTS 缩到 96px 后颜色糊成一块。

### 6.4 需要新增的两项自检（`库/audit.py` 现只有十项，没有这两项）

| # | 项 | 硬门 |
|---|---|---|
| ⑪ | 剪影差异（同种族两两之间，RTS 机位 96px） | Δ ≥ 30% |
| ⑫ | 武器可视性 | 占比 ≥ 8% / 最小厚度 ≥ 0.05m / 离地 ≥ 0.15m / 明度差 ≥ 0.15 |

两项都只对"同种族第 2 个及以后的兵种"生效；只有 1 个兵种时写 N/A。
**新增兵种时，必须和同种族已有兵种逐个比对，不能只跟自己比。**

## 9 历史教训（别重犯）

1. **v2 步兵只交了静态三网格**——引擎只能走"整体枢轴弹跳"兜底。
   ⇒ 规范 §8 的 ①④⑤（权重/接地/动作）是"能不能进引擎"的**底线，不是可选项**。
2. **v3 的方块人骨架未经验收** ⇒ 现在十项自检是强制的。
3. **弩手/农民仍是 v3 旧管线**（`add_death.py` exec 原脚本追加动作），
   仓库里两套管线并存，靠 `add_death.py` 桥接。迁移进 v4 约 1 天，属于下一轮待办。
4. **豺狼人两兵种剪影重合、武器在 RTS 下不可辨**（§6.1）——新增兵种时按 §6 执行，别再犯。
