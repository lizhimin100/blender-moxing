# 单位 v4 · 制作要点与经验

> 本文件是「方块人 V2 造型语言 + 建筑染色体系」这套单位管线的**唯一经验文档**。
> 数字全部来自脚本回执（\`库/audit.py\`）与 \`.blend\` 直读（\`库/dump_table.py\`），不手抄。

---

## 0 一句话结论

**联盟单位可以组件化，而且值得做**——把「形状」写成数据表、把「装配/绑骨/出图/自检」写成共用器之后，
步兵的重制版与 v2 原版 **三角面同为 3356、身高同为 1.755、脚底同为 0.0000**，
即「组件化没有改造型，只是让它第一次有了骨架和动作」。
野怪两个兵种则复用了同一套共用器的 **另一个模式**（逐面明度分档 + 五区染色 + 36/37 骨兽腿）。

## 2 组件化的四层结论

### 2.1 能共享的（已经共享）

| 层 | 内容 | 共享方式 |
|---|---|---|
| 形状语法 | 立方体 + 收分 + 剪切 + 倒角 + 边折痕 + 选择性 Catmull-Clark | \`kit.Unit.part/seg\` |
| 装配 | 命名 → 材质桶 → join → armature 修改器 → 父级 | \`kit.Unit.bind\` |
| 骨架 | 骨名/层级/枢轴高度/蒙皮权重 | \`kit.Unit.bone/rig\` + 各兵种 \`add_bones\` |
| 姿态与动作 | FK/IK、打点、缓动、循环检查 | \`poselib\` / \`野怪/anims.py\` |
| 出图与验收 | 三机位三点光、十项自检 | \`qclib\` / \`audit.py\` |

### 2.2 不能共享的（必须逐兵种写的）

- **部件表本身**：剪影是设计决策，不能参数化。步兵的部件表 45 条、农民 60 条、战士 90 条。
- **动作的关键帧**：节奏与重心是表演，不是公式。能共享的只有「打点方式」和「时长/循环/命中帧的规矩」。

### 2.3 组件化的两条硬接口（改这里 = 改所有单位）

1. **骨名 = 动作表的键**：联盟 \`root/hips/spine/chest/neck/head + shoulder/upperarm/forearm/hand
   + thigh/shin/foot/toe + weapon_?/shield\`（24~25 骨）；
   野怪 \`root/pelvis/spine.01-02/chest/neck.01-02/head/jaw + … + tail.01-03 + chain.01-03 + ear.L/R\`（36~37 骨）。
   **两套命名并存是故意的**：联盟三件是已验收资产（改名会废掉既有动作），野怪按任务书的规范自建。
   引擎只按动作名播放、不校验骨名，所以两套可以共存。
2. **材质名 = 染色协议的键**：联盟 \`主体 / team / team_trim\`；野怪 \`主体 / M_tribe / M_eye\`。
   见 §4.3 的坑：M_ 前缀一旦用错，整只单位会被引擎刷成灰色。

### 2.4 组件化的代价（如实说）

- 共用器每加一个开关（比如 \`slim\`），就多一条"只在某个兵种成立"的分支；**超过 3 条就该拆库**。
- 部件表的可读性比"少写几行"更重要：**一条部件 = 一行数据**，形状参数全部摊开写，
  不要用循环把不同形状折叠到一起（折叠过一版，改一个部件要读三个循环）。

## 3 骨架与蒙皮（硬约束）

### 3.1 坐标

- 脚底 z=0 **严格**贴合；原点在占地中心；正面 +Y（Blender）→ 导出后 −Z（Godot）。
- 归一化顺序固定：\`finish_geo()\` → \`normalize()\` → \`rig()\` → \`bind()\`。
  先归一化再建骨，骨与网格才共用同一个比例因子（反过来会脱钩，v2 就栽在这条上，见 §5 坑 6）。

### 3.2 蒙皮卫生

- 一块 = 一根骨、权重 1.0：**单顶点影响恒为 1（≤4）、归一化天然成立、没有零权重顶点**。
- 实测回执：战士 2116 顶点 / 斥候 1882 / 步兵 5116(重制前后同) —— \`zero=0 max_inf=1 unnorm=0\`。
- 为什么不做平滑权重：方块人的块面之间是"叠压"不是"连续"，平滑权重会把硬边揉成橡皮。

### 3.3 兽腿为什么必须三段

趾行腿的读图关键不是"弯"，是**反关节**：膝前顶 → 跗关节后收且抬高 → 长跖骨斜下 → 趾着地。
数据（斥候）：\`knee_fwd_of_hip=+0.171\`、\`hock_back_of_knee=−0.235\`、\`hock_z=0.281\`、\`tip_z=0.047\`。
只要这三条不满足，俯视下就是"人腿穿了狼鞋"。

## 4 染色体系（与建筑同一套，但野怪是另一套分区）

### 4.1 明度分档的两条实现路线

| | 联盟（方块人 v2/v3） | 野怪（本次） |
|---|---|---|
| 载体 | 5×5 纯色图集，**一件一格** | 8 区 × 4 档 纯色图集，**一面一格** |
| 分档来源 | 相邻件选不同色格（人工） | 面法线 · 主光 \`L=(0.49,0.58,0.68)\` 自动分四档 |
| 效果 | 大色块秩序 | 同一块躯干上天然 2~4 档，转折处自动出现"手绘暗部" |

四档系数（美术规范 §5.2，sRGB 值域）：亮 = 向白抬 24%（R×1.04/B×0.95）；
基 = 原色；暗 = ×0.72（B×1.08/R×0.97）；最暗 = ×0.50（B×1.16/R×0.94）。
亮/最暗极差 ≈ 1.97 倍。

### 4.2 野怪五区（唯一换色位只有 M_tribe）

\`M_fur_light #A8895C / M_fur #6B5B47 / M_fur_dark #3E3328 / M_hide #4A3624 /
M_hide_dark #3E2716 / M_bone #E3D9C4 / M_bone_dark #B8AC93 / M_iron #4C5058\` + \`M_tribe #8C3A2A\`。
实测换色位占比：战士 **3.65%**、斥候 **3.83%**（正视图朝镜头面投影面积 / 全身同口径）。
联盟步兵的 team 区实测 **14.0%**——盾面整块是队伍色，这是 v2 已验收的造型决策，
本次只做骨骼重制、不改造型；要回到 6~8% 只需把 \`shield_face\` 的 group 从 team 改成 body（一行）。

### 4.3 ★ 材质命名的坑（会让整只单位变灰）

引擎 \`材质库.zone_of()\` 只认 \`M_<zone>\`，查不到 zone 就走 \`pal.fallback = (0.62,0.62,0.60)\` → **整只变灰**。
所以：
- 图集主材质**不能**叫 \`M_xxx\`（会被当 zone 覆盖、贴图也会被丢掉）→ 用 \`主体\`（与方块人同一条旧资产通路）。
- 换色位必须叫 \`M_tribe\`，并在引擎调色板补一个 \`tribe\` 键（否则同样掉 fallback）。
- 眼点 \`M_eye\` 不在 zone 表里 → 原样保留，靠 GLB 自带的自发光工作。

## 5 踩过的九个坑（全部实测，按踩到时烧掉的时间排序）

1. **面数爆炸 = 倒角 + Catmull-Clark 叠加**。一件 \`bevel + sub\` 是 208 面，是纯盒子的 17 倍。
   纪律：**有机物只用 CC，硬表面只用倒角，永不叠加**。按这条把战士从 6452 压到 3608。
2. **武器把整只模型顶离地面**。锤头垂到 z=−0.021 → 归一化时整体上抬 21mm → 脚底浮空、\`toe_tip_z=0.071\`。
   修法：\`normalize()\` 之后必须打印 \`[zmin]\` 前四名，确认最低件是脚趾。
3. **手臂够不着握点**。手臂 reach 0.640（上臂 0.352 + 前臂 0.288）。把右手放在躯干侧面 (0.22,0.20,0.90)
   ——那已经在胸腔里了——IK 会把肘部顶到 x=0.489、双臂在腹前绞成一团。
   修法：**双手握持时两手都靠近中线，副手握在杆尾（grip2 = −0.095，即右手后方 9.5cm）**，
   杆从腕部往前伸 0.388；这样左手目标到左肩的距离是 0.48~0.59，留 0.05~0.16 余量。
4. **"第二张嘴"**。5 颗白骨横排在深色颈领下 → 一眼读成獠牙嘴。
   修法：骨串改成沿斜挎带的**一串垂挂**（6 颗，带角度），白骨不再成排横置。
5. **半空多一块方块**。v2 的 \`shield_grip\` 用的是**绝对坐标**（add_block），
   我把它当"盾局部偏移"塞进 shield_part → 木块飞到 (−0.57, 0.49, 1.40)。
   教训：移植部件表时，**同一个名字出现在两个 helper 里要逐个核对坐标系**。
6. **归一化顺序错 = 骨架与网格脱钩**（v2 的既有教训，本次照抄正确顺序避开）。
7. **自检读 pose 会被上一条动作污染**。\`arm.animation_data.action = None\` 不会重置 pose，
   实测趾行判定偏了 0.13m。修法：**自检一律读 rest 数据**（\`bone.head_local\`）。
8. **合并成网格后部件名就没了**。要按名做检查（比如"眼睛是否在 +Y"）就必须在 \`bind()\` 之前
   把每件的质心记进 \`u.meta\`，否则只能靠肉眼。
9. **根位移的判据是白名单，不是"全 0"**。\`walk_film/run_film\`（剪辑用）与 \`stagger\`（被打退）
   本来就该有位移；判据写成"除白名单外必须 0"才对，写成"全部 0"会把正确的动画判红。

## 6 动画标准（五个单位共用）

| 项 | 规矩 | 实测 |
|---|---|---|
| 帧率 | 30 fps | 全部 |
| 循环 | idle / walk 首末帧同姿态 | \`loop_Δ = 0.0\`（逐骨矩阵差的最大值） |
| 单次 | attack / hurt / death（death 停最后一帧） | — |
| 命中帧 | attack 的 40% 处 | 战士 (12−1)/27 = **40.7%**；斥候 (9−1)/21 = **38.1%**；步兵同战士 |
| hurt | ≤0.35s，可被任意动作打断 | 战士 0.33s / 斥候 0.30s / 步兵 0.33s |
| 根位移 | 除白名单外为 0 | 其余动作 0.00000 |
| 名字 | 引擎状态只用 idle/walk/attack/hurt/death(+cast)；剪辑附加件带明确后缀 | 见对照表 |

**表演结构**（不是硬约束，但决定"活物感"）：
- idle 里塞"小事件"：战士 4.5s 内做一次"抬手挠脖子 → 甩头"；斥候 5s 内做"警觉抬头 → 左看(停 0.3s)→ 右看(停 0.3s)→ 回正"。
- 三处微动叠加（下颌/耳/尾）是唯一的"活物"来源，幅度实测 0.16~0.46（四元数分量极差）。
- 长镜头会看出循环：所以另做 10s 不重复的 \`idle_alt\`（嗅空气 / 嗅地 / 甩尾 / 竖耳）。
- 死亡三段：受击 → 倒地 → 抽搐 → **末 0.4s 绝对静止**（战士 f28..f40 全等）。

## 8 已知取舍（没做的，写清楚）

1. \`联盟/步兵\` 的 6 个动作是我按"盾+剑"重写的，**没有沿用任何旧动作**（旧版本来就没有骨骼动作）；
   与弩手/农民的手感一致性靠"同一套时长/命中帧/根位移规矩"保证，而不是靠共用关键帧。
2. **弩手/农民的 death 是"补丁式"**：走的是 \`方块人_v3\` 的旧管线（\`add_death.py\` exec 原脚本再追加片段），
   没有迁进 v4 的共用器。理由：这两件的几何与动作已验收，重搬迁的收益小于风险。
   代价是仓库里同时存在两套管线——见 \`文档/自检报告.md\` 的"迁移建议"。
3. **不做 LOD、不做贴图法线**：与建筑/方块人一致（纯色图集 + 平面着色 + 明度分档）。
4. **盾挂在 chest 上**（不是前臂）：好处是"盾不乱飘"是结构保证；代价是盾臂不能独立做盾击动作。
5. **野怪的 M_tribe 需要在引擎调色板补 \`tribe\` 键**（本次未改游戏代码，只记录了改法）。
