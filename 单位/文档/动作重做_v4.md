# 动作重做 v4 —— 四件单位（2026-11-12）

> 口径没变：**模型一个顶点都不动，只重写动作**。
> 变的是"怎么判断一个动作做完了"：这一版先把**客观验收工具**建起来，再动手。

---

## 0 为什么要先建工具

上一版交付后仍然被打回，原因是**只靠眼睛**：

- 斥候"手撑腰"的病根，眼睛只能说"看着像"，说不出是哪块几何插进了哪块。
- 建了 `库/audit_anim.py` 之后，第一跑就量出 `hand_L×hips = 576 对三角面相交`——
  那只手不是"摆在胯边"，是**埋进胯里**的。改角度永远改不好。

三个新工具（都在 `库/`，四个单位通用）：

| 文件 | 作用 | 什么时候用 |
|---|---|---|
| `clip_lib.py` | 按顶点组拆骨、逐帧 BVH 互交、zmin、打滑、循环闭合 | 被下面两个调用 |
| `audit_anim.py` | **对出货 glb** 跑完整体检 | 每次导出后必跑 |
| `pose_check.py` | 内存里建单位 + 只建指定动作，14 s 出结果 | 改姿态时的高频循环 |
| `unit_shot.py` | 一次跑多条动作 × 多机位出图（含 96 px RTS） | 看构图/剪影 |

配套两个基础能力：

- `poselib2.Sole` + `poselib2.ground()`：**脚底是真的踩在地上**。
  取该骨 100% 权重的顶点换算到骨局部坐标，逐帧乘骨矩阵取最低点，差多少抬多少。
  比 `foot_clear()` 的解析式准 —— 后者在豺狼人的三趾爪上差 11 mm（全动作切地）。
- `poselib2.grip_at / sword_at / aim_weapon`：直接给"刃尖朝哪"，不再手调 pitch/roll/yaw。

**配对表**（`clip_lib.BODY × PROP`）只放"绝不允许相交"的组合；
上臂↔胸这种关节处天然互含的，单列在 `SOFT` 里给一个容忍阈值（40 对）。

## 1 豺狼人斥候：腰间低持（low guard）

### 病根（量化）

| 项 | 旧值 | 结果 |
|---|---|---|
| 后手握点 | `(-0.352, 0.176, 0.986)` | 在**胯的两侧**，而胯宽 0.47、披风壳半径 0.30 |
| `hand_L×hips` | — | **576 对相交**（手在胯里） |
| `weapon_L×hips` | — | 435 对（刀也在胯里） |
| `forearm_R×chest` | — | 247 对（前臂压在胸上） |

"肘不超过肩 ±0.05"这条旧判据是**不够的** —— 肘的角度对了，手仍然可以在身体里面。

### 新语法

```
蹲             dz −0.212，髋 −7 / 腰 −8 / 胸 −16（合计前压 31°），头 +20 把视线顶回来
一手在前        右掌心 (0.180, 0.404, 0.952)，刃尖 (−0.16, 0.90, −0.40) 朝前下
一手在后        左掌心 (−0.384, −0.324, 1.014)，刃尖 (−0.46, −0.62, −0.64) 朝后下外
躯干            hips_yaw +8 / chest_yaw +24（右肩在前，左肩收到背后）
脚              右脚前 (0.262, 0.232)、左脚后 (−0.256, −0.224)，yaw ±11/−19
```

三条硬约束（都是量出来的，不是审美判断）：

1. **后手必须在披风之外**。披风是 100% 单骨刚性壳，`z=1.0` 处椭圆 `rx 0.358 / ry 0.292`，
   手在 `x=−0.30` 时后表面在 `y=−0.27` —— 手放到 `y=−0.32` 以外才不穿。
   往前推到 `y=−0.24` 那一版，`hand_L×cape` 直接 326 对。
2. **躯干扭，手跟着扭**。握点写在"基准系"里，逐帧按 `hips_yaw+chest_yaw` 的差量绕竖轴转过去
   （`_yaw()`）。这样"手↔胯↔披风"的相对位置恒定，扫视、走路、出刀都不会因为胸一转
   就把后手推进披风。v4 早期版本手钉在世界坐标里，`hand_L×cape` 在 idle 扫视段涨到 489。
3. **前手要让开大腿前缘**。`z=0.95` 处大腿前缘在 `y≈0.265`，拳头后半 9 cm —— 掌心
   `y≥0.36` 才干净（扫描过 `y∈{0.36,0.39,0.42,0.45} × z∈{0.90,0.94,0.98}`，0.36 以上全清）。

### 五条动作

| 动作 | 帧 | 要点 |
|---|---|---|
| idle | 130 | 只动头（±30°扫视）+ 重心 1.2 cm + 一次换气；双手不离腰线 |
| walk | 30 | 腿走满（±0.20），手只做 ±1 cm 反相摆；`AH.ground` 保证支撑脚不飘 |
| attack | 40 | 右匕低刺（+0.29 m，肩不抬）→ 顿 3 帧 → 左匕低刺 → 回架 |
| hurt | 10 | 后仰侧闪，刀不散架 |
| death | 62 | 腿一软 → 跪坐垮塌 → 双匕摊在身侧、刃面朝上 |

攻击的第二段原本写的是"左匕横扫过身前"：实测 `forearm_L×chest = 878` ——
这副骨架**胸宽 0.50 m、臂长 0.62 m**，横跨身体必然把前臂压进胸里。改成同侧低刺。

### 结果

| 动作 | 改前 | 改后 |
|---|---|---|
| idle | `hand_L×hips 576`、`weapon_L×hips 435`、`forearm_R×chest 247` | 只剩 `upperarm_R/L×chest 41/76`（静止基线就有 60）、`hand_R×chest 17` |
| walk | 同类 700+ | `hand_R×thigh_R 35`、`upperarm_L×head 63`（兜帽 vs 三角肌） |
| attack | — | `hand_R×chest 89`（刺到最前时蹭到胸甲）、其余 ≤47 |
| 全部 | zmin −11 mm | **zmin +1.5 mm** |

`upperarm_L×head` 是**兜帽后缘压在左三角肌上**，被披风盖住看不见。已经用
`shoulder_L` 抬 8°+外旋 8° 从 254 对压到 113 对，再压就要动模型了 —— 记为已知瑕疵。

## 2 联盟步兵：举盾的构图重排

v3 的十二条骨架是对的（举盾 = 参数化姿态 + 每个状态各烤一版），**姿态立不住**：
盾立在胸前正中、盾面几乎平行画面，剑竖在脸前 —— 正面看是一面门板加一根杆子。

### 新构图

```
盾   盾心 (−0.256, 0.322, 0.986)，法线 (−0.24, 0.95, 0.22)（外偏 14°、上仰 13°）
     竖轴 (0.12, 0.09, 0.99)（顶端略外倾）
剑   右腕 (0.324, 0.162, 0.888)，剑轴 (0.14, 0.50, 0.85) —— 从前上方、盾的右缘挑出去
身   hips_yaw −10 / chest_yaw −12（左肩带盾前顶），dz −0.074，双脚前后错开
```

**握点必须换**。`weld_shield` 原来用静止姿态量出来的 `OFF_WRIST_L`（腕在盾心内下 18 cm，
那是"盾挂在体侧"的相对位置）。举盾时盾压到胸前，这个偏移会把腕推进胯里
（`hand_L×hips 63`）。v4 给 `weld_shield` 加了 `grip` 参数，举盾时用
`(−0.02, −0.112, −0.10)` = "腕在盾背中部"。

**十二条共用一份 `GS/GN/GU/GBODY/GFOOT`**，所以举着盾走 / 被打 / 待机，盾的位姿逐帧一致。

### 结果（出货 glb）

| 动作 | 状态 |
|---|---|
| guard_raise / guard_idle / guard_walk / guard_lower | **CLIP 全清** |
| guard_attack | `forearm_R×chest 10`、`shield×head 4` |
| guard_hurt | `shield×head 16`、`forearm_R×chest 4` |
| guard_death | zmin 0，`shield×head 26`、`weapon_R×chest 25` |
| idle / walk / attack / hurt / death | 只剩手蹭大腿（≤32）与剑柄蹭胸（≤96） |

旧资产里的 `cast` 是原模型遗留、手和剑从没焊过 —— 直接删掉，现在是干净的 12 条。

## 2.5 联盟农民：金袋组件 + 扛袋走

### 组件化

袋子跟"农民"没关系（运金子的农民、扛粮的苦工、商队的骡车都用同一袋），
所以抽成 `库/comp_sack.py`：

```python
import comp_sack as CS
SACK = CS.Sack(ROWS, MATS)        # 站表 (y,z,cx,宽,厚,倒角) + 材质
SACK.add_bone(arm, head, tail)    # 胸前加一根 sack 骨（父 chest）
mesh = SACK.build(arm)            # 建网格，100% 权重给 sack
mouth = SACK.mouth(P, MOUTH)      # 任意姿态下的袋口世界点
```

`unit_农民.py` 只剩站表和材质；`run_农民.py` 另外单独出 `农民_金袋.glb`。

### 站表：从 6 站改到 9 站

旧站表只有 6 站，袋口直接顶在肩上、袋身压在颈侧。新站表按"**袋口垂到胸前 → 细颈翻过肩
→ 袋身在肩后最鼓 → 袋尾沿背后垂下**"排：

```
袋口 (y +0.266, z 0.930)  细颈 (z 1.034)  袋身最鼓 (z 1.158)  袋尾 (z 0.920)
内壁全程 x ≤ −0.28
```

内壁必须让开：头/帽实测 `|x| ≤ 0.13`、胸 `±0.196`。压到 `x ≤ −0.28` 之后
`hand_L×head = 0`、`sack×head = 0`。

### 三条动作的公共层

`CARRY_BASE` + `_carry_frame()` + `_baked_carry()`：左手每帧由 `sack` 骨推袋口世界点再 IK
焊住；右臂按**胸的朝向**下垂（倒地时不会扫进胸口）；锄头 `prop_tool=0.001` 收起
（扛金子还拎着锄头会很怪）。

- `carry_gold` 36 f **扛着走**：步幅 0.105、负重前倾 5°、重心右偏 1.4 cm，袋子三轴小晃 1.2°/−1.6°/1.0°。
- `carry_gold_idle` 60 f 站立，袋子起伏 ±1.4°。
- `hurt` 9 f：扛着袋子被打，袋子被带得外甩 7° 离开脸。
- `death` 32 f：**往右**侧倒（袋子在左肩，往右倒袋子在身体上方，不会压进地面），f24~32 定格。

### 结果

| 动作 | zmin | loop | 主要 CLIP |
|---|---|---|---|
| carry_gold | +0.0012 | 0 | `sack×chest` 29 |
| carry_gold_idle | +0.0015 | 0 | `sack×chest` 27 |
| hurt | +0.0014 | 0 | `sack×chest` 27 |
| death | +0.0005 | — | `sack×chest` 27 / `hand_R×shin_R` 64（倒地 2 帧） |

`sack×chest 27~29` 是"袋内壁离胸 1~2 cm"的必然接触，被袋子自己挡住，在阈值内。

**注意 `run_农民.py` 里的 `sackXbody`**：它把整袋和三个身体网格直接做三角面互交
（不拆骨、把"压在肩垫上"也算相交），口径和 `clip_lib` 的分骨互交不同，别拿那个数当结论。

## 3 三个"最贵"的坑（这一轮新增）

1. **`legargs` 用 "R"/"L" 索引，不是骨名**。`ground()` 里写成 `if "foot_"+side not in
   P.legargs` → 永远 continue，落地校正静默失效，zmin 一直 −11 mm。
   加了 per-frame 的 zmin 归因打印（`@f42(toe_L)`）才看出来。
2. **`aim()` 只改朝向不改 T**。量高度前必须 `solve_T()`，否则用的是上一帧的骨根位置
   （实测左脚差 17 cm）。
3. **刚性壳（披风/裙甲）会吃掉一切"身后"的姿势**。手在背后的动作，要么把手放到壳外面，
   要么让壳跟着躯干转 —— 没有第三条路。

## 4 自检清单（以后每个单位都过一遍）

```
blender -b --factory-startup --python 库/pose_check.py -- <unit_dir> <unit> <anims>
blender -b --factory-startup --python 库/run_unit.py  -- <unit_dir> <unit>     # 或 run_xxx.py
blender -b --factory-startup --python 库/audit_anim.py -- <出货.glb> --pairs all
```

- `zmin ≥ −0.002`（脚底真的在地上）
- 循环动作 `loop < 1e-6`
- `CLIP` 里 `hand_*/weapon_*/shield/sack × head/chest/hips` 越接近 0 越好；
  `upperarm×chest` 有静止基线（60 对），不算问题
- 96 px 缩略图能指认动作（`unit_shot --rts` / `qc_unit --rts96`）
