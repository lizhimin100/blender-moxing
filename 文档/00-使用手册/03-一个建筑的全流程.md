# 一个建筑是怎么做出来的

> 从"我想做一座 X"到"Godot 里能拖进去用"，一共 12 步，其中 4 个是**卡口**（不过不许往下走）。
> 本文用 2026-11 的十三座资产当例子，命令都能直接抄。

---

## 第 0 步 · 先把话说清楚（卡口 ①）

需求进模型之前必须答出四件事，缺一件就会返工：

1. **它是什么类型** —— 生产建筑 / 防御建筑 / 中立场景 / 纯道具？
2. **占地多大** —— 给一个 m×m 的范围，不是"大一点"。
3. **一个识别点** —— 一眼看过去凭什么认出它？（地牢 = 掀顶的方塔；蒸汽车坊 = 长坡山墙）
4. **和谁站一起** —— 旁边是铁匠铺还是神秘圣地？决定色温和明度。

模板见 `04-下需求模板.md`。

---

## 第 1 步 · 定风格（卡口 ②）

不确定就先看 `docs/审美/对照台_地牢.png` 四张图，指一个方向，写进
`docs/审美/风格档案.md`。别在这一步含糊 —— 造型返工一次等于重建半座。

## 第 2 步 · 写 `<x>_model.py`

一个建筑一个文件，`class Model` 继承（或照抄）已有的那座。骨架固定：

```
__init__      → 尺寸常量、材质句柄 M = L.all_materials()
build(smooth) → 按分区依次调用：基座 → 主体 → 屋顶 → 门窗 → 台面道具 → 场地
finalize()    → L.finalize(objs, smooth=…)   ← Bevel + Subdivision 在这里塌，低模不受影响
```

三条不可商量的约定：

| 约定 | 值 | 为什么 |
|---|---|---|
| 单位 | 1 unit = 1 m | 进引擎不用缩放 |
| 原点 | 占地中心，z=0 是地面 | 摆放时不用手动抬 |
| 朝向 | 建模期 +Y 正面（导出后 −Z） | 引擎里默认面向相机方向 |

**几何即代码**：不手捏、不用雕刻、不贴细节法线。所有形态由参数决定，
所以"改高 0.5 m"是一行数字，不是重做。

**构件命名**：`<分区前缀>_<构件>`（`gt_` 门楼 / `tw_` 塔 / `pd_` 台基 / `pro_` 道具）。
体检、LOD 裁剪、人群染色都靠这个名字找东西。

## 第 3 步 · 看形体（30 秒一轮）

```bash
echo dg_model > blender/bs_v6/_target.txt
"D:/360安全浏览器下载/blender.exe" -b --python blender/bs_v6/dl_quick.py
```

出 `docs/<资产>/v1/quick_smooth.png`（3/4）和 `quick_smooth_top.png`（俯视）。
**先看俯视** —— 俯视能站住的构图，3/4 一定不差；反过来不成立。

这一轮要看到的东西（这是美术判断，不是技术检查）：

- 剪影能不能用一句话说清
- 主次体量宽度比是不是 1 : 0.6 : 0.35 左右（一样宽 = 没有主角）
- 明度有没有三档（亮 / 中 / 暗），两档会糊成纸模
- 场地是不是空的（俯视有四分之一空着 = 构图失败）

## 第 4 步 · 体检（卡口 ③）

```bash
"D:/360安全浏览器下载/blender.exe" -b --python blender/bs_v6/dl_align.py
```

七件一起跑，结果写 `docs/<资产>/v1/align.txt`。放行条件：

| 指标 | 阈值 | 含义 |
|---|---|---|
| `CLIP_CROSS` | **0** | 两个构件互相穿过（穿模） |
| `COPLANAR_UP` | **0** | 两个面同高（共面闪烁） |
| `FLOAT` | **0** | 构件悬空、没有支撑 |
| `grounded` | true | 最低点贴地 |
| `front_ok` | true | 正面朝 −Z |

修法是确定性的，不要靠挪 1 mm 试：

- **共面** → 让一个面比另一个高/低 1.5 mm 以上（压顶、檐板、线脚都是这类）
- **悬空** → 找支撑（托石、勒脚、底梁），不是往下平移
- **穿模** → 改尺寸，不要靠缩 2% 蒙混（缩完还是穿，只是看不出来）

体检报告的残余项（比如吊灯两根辐条同高）要写进 `报告.md`，说明"不可见、已知"。

## 第 5 步 · 阵营色

```bash
"D:/360安全浏览器下载/blender.exe" -b --python blender/bs_v6/dl_teamshare.py
```

三个机位量 `team + team_trim` 的可见像素占比。人族九座是 **6–9%**；
废墟类（地牢/入口）刻意压到 **5% 上下**，因为它们是失落帝国，不是军营。

**规则：同一座建筑的队色横线不超过两道。** 试过三道（垛口 + 台基 + 外梯），
正视图直接变成"蓝条纹的石头"。

## 第 6 步 · 导出低模 + 细分

```bash
"D:/360安全浏览器下载/blender.exe" -b --python blender/bs_v6/dl_export.py
```

原理：低模是原拓扑；细分版走 `finalize()` 里的 Bevel + Subdivision 修改器栈。
**不要为两档各写一份模型。** 输出 `<名>.glb` / `<名>_低模.glb`。

---

## 第 7 步 · 图集 + 手游三档（卡口 ④）

```bash
"D:/360安全浏览器下载/blender.exe" -b --python blender/bs_v6/export_mobile.py
```

把 19–20 个材质压到 **4 个**（主体图集 / team / team_trim / 自发光），再出三级 LOD。

- 图集 5×8 = 40 格，512²，**材质只能追加到 `ATLAS_ORDER` 末尾**（改顺序 = 改 UV）
- 三档共用同一张图集（切档不掉材质、不重传贴图）
- 预算按低模实测 ×1.2 留余量，超了就报 `over_budget`

---

## 第 8 步 · 建造动画

```bash
"D:/360安全浏览器下载/blender.exe" -b --python blender/bs_v6/dl_cs.py
```

v2 的做法是 **世界 Z 显影**：建筑本体一个字节都不动，靠引擎侧逐片元裁剪"长出来"，
外加 3–6 步脚手架。硬指标：

```
BODY_RIG 0 / BODY_TRIS 0 / BVH_CROSS 0 / BOX_TALL 0 / SCAF_OVER 0
```

产物 `<名>_建造.glb` + `docs/建造系统/参数/<名>.json`（Godot 侧读它）。

> 高度 < 5.2 m 的建筑只搭 1–2 步架（三步 6.6 m 会压过 3.5 m 的酒馆）。

## 第 11 步 · 登记

新资产要接进这些表（少一个就会出现"导出了但预览里没有"）：

```
export_mobile.BUILDINGS      图集 + LOD
bs_atlas.LOD_KEEP_*          远景保留哪些构件
cs_all.BUILDINGS            批量建造
build/mk_build_preview.py   ORDER（建造预览台的顺序）
icon_shots.targets          图标
icon_post.BUILDINGS         图标合成
预览.html 的 MODELS          本地预览
```

---

## 第 12 步 · 收尾

1. `docs/<资产>/v1/报告.md`：尺寸、三角面、体检、阵营色、取舍（**为什么这么做**，不是做了什么）
2. `CHANGELOG.md` 加一节
3. 删中间产物：`docs/_tmp/`、`quick_*.png`、`_target.txt`
4. `ls assets/<资产>` —— 应该只有图标 + GLB
5. `python blender/bs_v6/assets_path.py` 刷新索引

## 时间参考（2026-11 实测）

| 阶段 | 耗时 | 占比 |
|---|---|---|
| 写 model.py（第一版） | 2–4 h | 40% |
| 看片 → 改 → 再看片 | 1–3 h | 30% |
| 体检修正 | 0.5–1.5 h | 15% |
| 导出 / 图集 / 建造 / 图标 / 文档 | 1–1.5 h | 15% |

**返工几乎全部来自第 0 步和第 1 步。** 造型阶段的每一小时，等于后面省三小时。
