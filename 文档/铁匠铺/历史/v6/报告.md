# 铁匠铺 v6 · 本轮交付说明

> 目标：把「灰扑扑、没有染色区、一堆球」的铁匠铺，重做成一件**能直接进 Godot 的**低模 + 细分小品资产。
> 工作方式：Blender 5.2 内用 bpy 参数化建模（几何即代码），经 DSH Blender 插件通道（`/act`）驱动，
> 全程可复跑：`blender/bs_v6/` 里的四个脚本就是完整管线。

---

## 1. 三条反馈 → 三条改法

| 你的反馈 | 根因（查证过的） | 本轮怎么改 |
|---|---|---|
| **「还没做染色区域」** | v5 的阵营色是**着色器功能**：TC1 遮罩存在 ORM.a 里，靠 `team_tint.gdshader` 采样。Blender/EEVEE 里没有这份 GLSL，于是遮罩区一律渲染成白色 —— 出图看起来就是"没有染色区"。 | 阵营色改成**两个独立的 PBR 材质**：`team`（主色）+ `team_trim`（辅色）。不依赖任何着色器，谁打开 GLB 都能看见。Godot 里换色 = 改这两个材质的 albedo（脚本 `blacksmith_v6_team.gd` 已写好）。 |
| **「感觉灰扑扑」** | ① 色卡本身就压得暗（`stone #8D949B`、`roof #5F5446`）；② 全包只有石/木/瓦三种低饱和，没有"点"；③ 出图用的是灰蓝补光 + 环境反射 1.35，把所有面压平。 | ① 重排色卡：石走中性冷灰、木走暖橙棕、瓦走深蓝黑，三者**色相差拉满**；② 加两处强饱和点：蓝金纹章 + 炉火橙；③ 灯光改"暖主光（左上前）+ 冷补光（右后）+ 暖反弹"，背景去掉天空蓝。 |
| **「到处都是球」** | v5 屋面是"每皮瓦一块小方盒"逐块拼的（`每皮 0.22 / 露明 0.16 / 每 3 皮错缝`），一个屋面两百多块小凸起；再叠上 `shinle` 贴图的高频噪声，远处读成一片圆疙瘩。山墙、烟囱箍同理。 | 屋面改成**连续瓦垄压条**（每坡 8 道整条），读作"一排排瓦"而不是"一堆球"；所有"圆"重新定义为**少边回转体**（12/16 边），靠细分磨圆，不再用阶梯近似，也**一个球体都没有**（无 `uv_sphere` / `ico_sphere`）。 |

## 2. 低模 → 曲面细分（两次交付）

| | 低模 | 细分版 |
|---|---|---|
| 三角面 | **5,911** | **148,738** |
| 顶点 | 3,424 | 74,747 |
| 拓扑 | 原始四边面，**全平面着色** | Bevel(2 段, 30°) + Catmull-Clark 1 级，平滑着色 |
| 读出 | 棱角分明，切面反光 | 棱被磨圆 2–4 cm，风格化硬表面 |

流程写在 `blender/bs_v6/bslib.py::finalize()`：
`Bevel → Subdivision` 塌修改器 → 按 32° 面夹角自动标记锐边 → 平滑着色。
**低模阶段的所有尺寸一个都没改**，细分只负责磨圆棱边 —— 这是"先 low poly 再细分"的正确顺序：
比例在低模阶段定死，细分不改善造型，只改善表面。

对照图：`docs/bs_v6/blacksmith_v6_lowpoly.png` 与 `docs/bs_v6/blacksmith_v6.png` 是**同一机位**。

## 3. 形体重做（对齐参考图 `参考图/铁匠铺.png`）

v5 的铁匠铺是"一个大屋面 + 一个烟囱"，职责构件（炉口）看不见。本轮重排为 **L 形 + 两个山墙 + 一个凸出炉膛龛**：

```
       ┌──────────── 主屋 8.0 × 6.4 m，双坡 41°，屋脊 8.20 m
       │   前山墙：半木构（大横梁 / 中柱 / 双横枋 / 斜撑）
       │   山墙尖：金十字（对应参考图屋脊上的金色十字）
   ┌───┴───┐   ┌──────────────┐
   │门廊翼 │   │  炉膛龛       │ ← 凸出正立面 1.86 m，敞口拱券 3.10 m 宽
   │2.44 m │   │  自坡瓦檐     │    内壁深色，火塘 + 三簇火舌 + 炭块
   │ 拱窗  │   └──────┬───────┘
   │ 拱门  │          │ 烟囱 1.68 × 1.88，顶 10.70 m（高出屋脊 2.5 m）
   └───────┘          │ 两道石箍 + 一道阵营蓝箍 + 一道金箍
```

- **屋脊方向**：沿 Y（前后），所以正面是**山墙**而不是檐口 —— 这是参考图的读法，
  v5 里屋脊沿 X，正面只能看到一条檐口，屋顶占了大半画面。
- **炉膛龛**：从前墙**凸出**而不是往里凹。凹龛会做出 1.6 m 深的"拱顶天花"，
  从仰角看就是一块横搁板；凸龛的拱券只有 0.46 m 厚，读作真正的石拱。
- **烟囱**：独立砌到 10.70 m，两道石箍做出收分节奏，阵营色箍在 6.90 m（视线高度）。
- **半木构山墙**：檐上大横梁 + 中柱 + 双横枋 + 斜撑，全部 `wood_dark`，
  与浅色石墙形成硬对比 —— 这是"西幻作坊"最省成本的身份信号。
- **道具**：铁砧（三件式，含 horn）、两只陶罐、两个煤筐、磨石架、原木堆（端面带年轮 + 阵营色捆绳）、
  工具墙、门前提灯。

## 4. 染色区清单（换这两个材质就全变）

| 材质 | 出现位置 | 可见面积占比（正视，粗估） |
|---|---|---|
| `team` | 烟囱蓝箍、三面盾的盾底、门楣横匾、三扇窗的窗楣、两面燕尾垂旗、原木捆绳 | ≈ 4.5% |
| `team_trim` | 盾牌金边 + 铁砧纹章、垂旗金边、门楣上沿、烟囱金箍、屋脊金十字 | ≈ 2.0% |

合计约 **6.5%** 的可见表面是阵营色，且分布在**低（门楣 / 窗楣 / 捆绳）、中（烟囱箍 / 盾）、高（山墙垂旗 / 金十字）** 三个高度带 ——
沿用项目里 6–9% 的口径，但换了实现方式（材质而不是着色器遮罩）。

> 这里不是严格测量值：口径是"正视投影里阵营色像素占比"，我用渲染图目测 + 面积估算。
> 真要做成可测项，得按 `build/check_teamcolor.py` 那套 z-buffer 正交投影重算一遍。

## 6. 管线（可复跑）

```bash
PY="C:/Users/箭竹/.workbuddy/binaries/python/envs/wb_build/Scripts/python.exe"

$PY build/bl_rt.py ping                        # 通道自检（DSH Blender 插件 /doctor）
$PY build/bl_rt.py act blender/bs_v6/bs_build.py   # 建两版 + 导出 GLB + 数值回执
$PY build/bl_rt.py act blender/bs_v6/bs_shots.py   # 出图（docs/bs_v6/）
$PY build/bl_rt.py act blender/bs_v6/bs_verify.py  # 把导出的 GLB 重新导入回查
```

`build/bl_rt.py` 是本仓库已有的通道客户端：把 DSH Blender 插件的 `blender_rt_do` 包成命令行，
所以这些脚本既能在本会话里跑，也能在没有 DSH 宿主时直接跑。

源文件：
```
blender/bs_v6/bslib.py     几何基元（拉伸 / 回转体 / 拱带 / 筝形盾 / 倒角+细分塌陷 / 按材质合并）
blender/bs_v6/bs_model.py  铁匠铺的形体定义（纯数据 + 构件函数，没有魔法偏移）
blender/bs_v6/bs_build.py  建两版、导出 GLB
blender/bs_v6/bs_shots.py  固定机位出图（主图 / 正 / 侧 / 近景 / 低模对照）
blender/bs_v6/bs_probe.py  射线诊断（把某个像素反查成对象名 + 材质，用来定位"那块东西到底是什么"）
blender/bs_v6/bs_verify.py 导出后回查
blend/bs_v6/blacksmith_v6.blend   工程源文件（含相机 / 灯光 / 细分版）
```

## 7. 验证到哪一步（诚实清单）

**已实测**

- 两版 GLB 都能被 Blender 重新导入，材质名与数量一致，包围盒一致（`bs_verify.py`）。
- 低模 5,911 tri / 细分 148,738 tri，16 材质，`z_min = -0.015 m`（贴地，没有穿地）。
- 朝向：正面朝 −Z（Blender +Y → glTF −Z），原点在占地中心。
- 没有球体：全模型没有 `uv_sphere` / `ico_sphere`，圆都是 8–16 边回转体。
- 没有 Z-fighting：屋面是**抬到石面之上的独立板**（法向偏移 0.14 m + 板厚），
  山墙、墙体、面层之间一律有间隙 —— 这是上一版"屋顶与石面共面打架"的直接修正。

**没做**

- **没有在 Godot 里真跑过**：本机没有 Godot 可执行文件，`.tscn` / `.gd` 是按 4.x 语法手写 + 静态检查的，
  未经过引擎编译。第一次导入请留意 `ext_resource` 路径与 `class_name` 冲突。
- **没有在真实 GPU 上做 120 帧闪烁像素差测试**（沿用项目里的老缺口）。
- **没有做 LOD 自动生成对照**；低模版可以当 LOD1，但切换距离要自己调。
- **阵营色占比是估算**，不是按 z-buffer 投影统计的数字。
