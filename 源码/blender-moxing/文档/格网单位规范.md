# 格网单位规范 v1（唯一真源 · 格网档）

> **触发词**：提示词里出现「格网模型 / 格网单位 / 格网档 / voxel grid / 格子模型」→ 按本文件执行，
> 不要走 `单位资产规范.md` 的方块人流程，也不要走 `精模单位_秘法.md` 的倒角流程。
>
> **定位**：单位分两档，本文件管**低档（格网）**。
>
> | 档 | 语言 | 谁负责 | 用途 |
> |---|---|---|---|
> | **格网档（本文件）** | 整数格 + 顶点色 + 平面着色 | **agent 全权**（可批量生成、可自检） | 全部量产兵种 |
> | 精模档（`精模单位_秘法.md`） | 倒角硬边 + 分段曲面 | 人主导 | 门面单位、宣传、图标特写 |
>
> 与 `单位资产规范.md` 的关系：**那本管"怎么存、怎么交、怎么进引擎"（通用），本文件管"格网档怎么建"（专用）。**
> 冲突时：骨骼白名单、材质名、动作名、坐标、预算、验收十项 **以那本为准**；格网的具体做法以本文件为准。

## 0 三条不可动

1. **格子是唯一数据源，mesh 是派生物。** 任何环节不许直接编辑 mesh（不许 decimate、不许手动挪点、不许重拓扑）。
2. **一块 = 一根骨 = 权重 1.0（刚性）。** 不许平滑权重、不许画权重。
3. **静止帧骨缩放永远是 1.0。** 拉伸只活在动作帧里。

违反任何一条，风格立刻从"格网"退回"低模"，且 LOD / 自检 / 变体三条流水线同时失效。

## 1 网格常量（基准 v1，冻结）

| 项 | 值 | 说明 |
|---|---|---|
| 格边长 `CELL` | **0.1 m** | 全项目唯一。不许 0.07（Q 版）也不许 0.05（过密） |
| 基准总高 | **17 格 = 1.70 m** | 身高变体只允许 16 / 17 / 18 三档（±0.1 m） |
| 头 | **4 格宽 × 4 深 × 4 高**（x −2..2, y −2..2, z 13..17） | 4.25 头身。**禁止 8 格宽大头**（那是吉祥物，不是兵） |
| 躯干 | 6 格宽（x −3..3）, y −2..2, z 9..13 | 肩宽含臂共 10 格 |
| 手臂 | 2 格宽 × 2 深, x ±3..±5, z 8..13 | 每侧一根上臂 + 一根前臂 |
| 腿 | 每侧 2 格宽（x 0..2 / −2..0）, 2 格深 | 双足合计 4 格宽 |
| 关节 z（格） | 地面 **0** / 靴口 **2** / 膝 **6** / 胯 **9** / 肩颈 **13** / 头顶 **17** | 骨骼 head/tail 一律落在这六条线上 |
| 眼 | **slab 0.6 × 0.5 格**，凸出格面 0.005 m | **不许用整格眼**（整格眼 = 四倍大，读作玩偶） |
| 腮红 / 嘴 | slab 0.4 格 / 0.3 格 | 同上 |
| 描边 | 反向外壳，宽 **0.2 格 = 0.02 m**，单色 `#241C2C` | 只加在单位上，建筑不加 |
| 材质 | **3 个固定名**：`主体` / `team` / `team_trim` | 见 §4 |

坐标：1 单位 = 1 m；+Z 向上；**正面 +Y**（导出后 = Godot −Z）；脚底 z=0；原点在双足中间。

## 2 基准 + 派生（本档的核心机制）

### 2.1 基准锁死什么

基准 = `库/voxbase.py` 的常量表 + `<阵营>/基准/unit_基准.py` 的 `build(overrides)`。
下面这些**任何派生都不许改**，改了就是另一个风格：

格边长 · 总高 · 头 4 格宽 · 眼 slab 尺寸 · 六条关节 z 线 · 描边宽 · 材质名 ·
色板的明度四档 · 部件命名（= 骨名）· 面朝 +Y · 脚底 z=0

### 2.2 派生只许改三样

| # | 可改 | 上限 | 例 |
|---|---|---|---|
| ① **体量** | 肩宽 / 腿长 / 身高，**整数格** ±2 | 身高只准 16/17/18 | 矮壮兵 16 格 + 肩 7 格 |
| ② **一件超规格大件** | 1 件，占剪影 ≥8% | 必须跳出头/肩轮廓 | 斗笠、大方盾、长枪、大锤、火药桶、旗杆 |
| ③ **装饰** | 盔 / 披 / 带 / 纹 / 背包，累计 ≤3 件 | 单件 ≤2 格厚 | 护肩、腰垂、背囊 |

**登记纪律**：每个派生文件头必须写
```python
BASE = "v1"                    # 从哪一版基准起
DIFF = ("体量:身高-1格", "大件:长枪", "装饰:护肩")   # 只列这三类
```

### 2.3 风格一致靠什么

不是靠"共用基准"，是靠**偏差被强制取整**。手工作业每件漂 3–5%，九件就是九个风格；格网里偏差只能是整格，漂不了。

### 2.4 防同质化（硬门）

把同阵营全部兵种涂成同一颜色、只留剪影，缩到 **96 px**，逐个还能认出来 —— 不满足就不算派生成功。
沿用 `单位资产规范.md` §13 三条硬指标，只把度量单位换算成格：

| 指标 | 格网档门槛 |
|---|---|
| 识别点 | **≥3 个**，分布在 ① 头颈 ② 躯干肩 ③ 下肢+武器 三个高度带，每带至少 1 件、≥1 格 |
| 武器/大件投影 | ≥8%（RTS 机位，口径同 §13.1-B）；主件最小厚度 ≥1 格（0.1 m）；离地 ≥1.5 格 |
| 剪影差 | 同族两两，96 px 剪影 Δ ≥ 30% |
| 体型差 | **禁止整体缩放**；≥1 格差（6→7 格肩宽即 14%，自动满足原 8% 门槛） |

### 2.5 基准版本化（唯一的致命项）

基准一改 = 全部兵种返工。所以：
- 基准封板为 `v1`，改动必须新开 `v2` 并在本文档 §10 登记原因。
- 派生文件写死 `BASE = "v1"`；基准升版后，未迁移的派生仍按 v1 出图，不许半迁。

## 3 建模手法（格网原语）

每个部件 = 一组整数格 + 一张色。原语只有六个，够用：

| 原语 | 作用 | 纪律 |
|---|---|---|
| `box(x0,x1, y0,y1, z0,z1)` | 填一格区间 | 半开区间；整数；不许浮点 |
| `put(x,y,z)` | 单格 | 用于点缀、纽扣、铆钉 |
| `cut(...)` | 挖 | 用来做门襟、领口、袖窿 |
| `tint(...)` | 只改区间内**已有格**的色 | 做腰带压边、袖口，不增面 |
| `slab(...)` | 亚格薄片 | **只给五官和图案**；凸出 0.005 m；不许承重 |
| `sleeve(...)` | 关节套筒 | 见 §5.2，**必须预埋**，事后补不了 |

面剔除：同一部件内，相邻格之间的面不出。跨部件不剔除（套筒靠重叠遮缝）。

## 4 颜色与队色（沿用引擎染色通路）

- **不要为了少一个材质去改引擎染色通路。** 引擎 `zone_of()` 按材质名分区，
  所以格网档固定三槽：`主体`（固有色）/ `team`（队色）/ `team_trim`（队色辅色）。
  draw call 3，优于方块人档的 3 个网格对象。
- **无 UV、无贴图、无图集。颜色一律顶点色。** 这是格网档最大的流水线收益：
  图集（5×8 / 512² / 内缩 22）与 `EMISSIVE_MATS` 索引表**整个跳过**，新增配色不改索引。
- 同一材质内部，**明暗靠顶点色分档**（= 队色的 `T / T- / T-- / T+` 倍数机制）：
  `team` 材质里顶点色存"明度倍数"，引擎乘队伍色。所以同一条队色带上能出"主体 + 亮边"两级，不占额外材质。

**队色标准值（不许改）**

| 阵营 | `team` | `team_trim` |
|---|---|---|
| 联盟 | `#2E5FB4` | `#F1CD79` |
| 失落帝国 | `#743A2E` | `#A99578` |

**队色占比**：正视图投影 **6–9%**（沿用建筑口径，比方块人的 6–8% 略放宽，因为单材质下明暗分档会吃掉一点面积）。
在格网里这非常好控：**数格子**。一条绕身 1 格高的腰带 + 一圈 0.5 格袖口，就落在 7% 附近。
一条铁律：**队色横线一件不超过两道**（同建筑的规矩）。

## 5 骨骼与拉伸

### 5.1 骨骼

- 沿用 `单位资产规范.md` §2.3 白名单，联盟 **24–25 根**，后缀 `_R/_L`；野怪 36–37 根，后缀 `.R/.L`。不许混用。
- **兵器辅骨**是唯一允许的追加，且必须满足三条：
  ① 只挂在 `weapon_L` / `weapon_R` 下面；② 只由需要它的兵种写进 `Grid.extra_bones`，
  不改进人形白名单（别的兵种骨数不变）；③ 顶上不带任何身体顶点。
  已登记：`bow_up` / `bow_dn`（弓弦上下两段，弓箭手用 → 26 根，见 §5.3 例外条）。
- 骨 head/tail **必须落在 §1 的六条关节线上**（格数 × 0.1），不许手调零点几米。
  兵器辅骨不在六条关节线上，但必须落在**兵器几何上**（弓梢 / 弦中点 / 刀柄端面）。
- 刚性蒙皮：每块 100% 一根骨。这与精模档"一块一根骨、权重 1.0"是同一条规矩，照搬。

### 5.2 关节套筒（必须预埋在基准里）

拉伸一定会在关节处露洞。解法：**父部件朝子部件方向多伸 1 格，染深两档**，做成套筒。
被拉长时露出的就是这根深色套筒，读作关节护垫，而不是洞。

- 位置：肩 / 肘 / 胯 / 膝 四处（踝不拉，不需要）
- 尺寸：1 格长（沿骨轴）+ 比子部件截面小 1 格
- 颜色：该部件固有色**压暗两级**（明度 −0.12 左右）
- 判定：`套筒覆盖率 = 覆盖的关节数 / 4`，必须 = 1.0

### 5.3 拉伸规则（阈值是硬门）

| 项 | 门槛 |
|---|---|
| 单骨缩放 | **≤ 1.35**（沿骨轴，另两轴可反向压到 1/√s 保持体积感） |
| 整件冲击帧 | **≤ 1.6** |
| 持续帧数 | 3–5 帧，之后必须回 1.0 |
| 静止帧 | 缩放 = 1.0（逐帧断言） |
| 验收 | 一律按 **posed bbox** 测，不许用静止 bbox 冒充 |
| **例外：兵器辅骨** | 弦 / 绳这类**道具形变**不受上面两条约束（弓弦实测 1.66），但要在资产文档登记。理由：橡皮感来自"关节被拉长"，道具本来就是软的 |

**这条门槛管的是关节，不管道具。** 弓弦拉满必须变长（弦长 = 弓梢到拉弦手的距离），
不放宽就只能"弦不跟着手走"——那比橡皮更假。

**继承陷阱**：非等比骨缩放会传给子骨。拉长 `shin` 时 `foot` 会跟着变长 —— 必须对 `foot` 给 `scale = 1/s` 反向补偿，
否则脚掌变成拖鞋。同理 `upperarm` 拉伸时 `hand` 要补偿。**这条写进动画检查脚本，不靠人看。**

**美学上限**：单骨超过 1.35 就开始读作"橡皮"，超过 1.6 格网语言直接消失（方块变长方条）。

## 6 LOD（必须从格子降采样）

| 档 | 做法 |
|---|---|
| 近 | 全量 |
| 中 | 格子按 **2×2×2 取多数色** 降采样，贴片（extras）原样保留 |
| 远 | 同一格宽（step 2），**丢掉薄贴片**（最短边 < 0.45 格）—— 省面靠这个，不靠再放大格块 |
| **禁止** | 在 mesh 上 decimate / 减面 —— 顶点组会丢，权重错乱，LOD 抖动 |

**降采样是"格块变大"，不是"模型变小"。** 合并后每个格块占 `step` 个半格（`Part.step`），
总尺寸、骨架、贴片坐标**全都不动**。v3 的第一版把格索引除以 2、却忘了把格块放大，于是
中档 LOD 是个半尺寸小人 + 1.7 m 的骨架 + 原尺寸的枪和贴片，渲染出来是一堆漂浮的板片
（用户原话"低模直接不成人样"）。远档也别用 step 3：手臂的 3 格块会胖到 0.6 m 宽，
正好把挂在身侧的弓吞进去 —— 远档变成"没有弓的弓箭手"。

降采样后必须保持：脚底 z=0、总高不变（取整规则固定为"优先保留最上和最下一层"）、队色占比仍在 6–9%。

## 7 验收（十项沿用 + 三条格网专属）

`单位资产规范.md` §8 的十项全部保留，其中三项改用格网口径实现：

| # | 项 | 格网口径 |
|---|---|---|
| ① | 零权重 / 影响数 | `zero=0 max_inf=1`（刚性蒙皮必须恰好 1） |
| ② | 脚底 z=0 | 格层面判：最低格 z 索引 = 0 |
| ③ | 正面 +Y | 两眼 slab 的 y 均 > 头中心 y（不要用"重心"糊过去） |

**三条格网专属（新增，机器可判）**

| # | 项 | 硬门 |
|---|---|---|
| ⑬ | 格网越界 | 所有格索引 ∈ 声明包围盒；且总高 = 16/17/18 格 |
| ⑭ | 孤立方块 | 同部件内六面不相邻的格 = **0** |
| ⑮ | 部件穿模 | 非父子部件 AABB 相交对数 = **0**；父子允许重叠（那是套筒） |

⑬⑭⑮ 全是整数运算，**不需要渲染、不需要截图**。这就是"agent 能自己写完自己验"的判据。
渲染只用来回答一个问题：**96 px 下还认不认得出是哪个兵种。**

## 8 与现有管线的接法

| 环节 | 格网档怎么做 |
|---|---|
| 建模 | `<阵营>/基准/unit_基准.py` 派生，只改 §2.2 三类 |
| 导出 | 1 个 GLB；1 个 mesh（3 材质槽）+ 1 个骨架；`export_texcoords=False`（本来就没 UV） |
| 动作 | 沿用六名：`idle / walk / attack / hurt / death / cast`，循环首末一致，根位移白名单同 §2.5 |
| 图集 | **跳过**（顶点色代替） |
| 图标 | 直接用 GLB 渲（`iconlib`），不许画 |
| 归档 | `assets/单位/<阵营>/<名>/`：`<名>.glb` + `<名>_图标.png` + `<名>_手游_近/中/远.glb` |

**不要动**建筑管线（`blender/bs_v6/`）与精模档（`blender-moxing/秘法/`）。三档并行，互不影响。

## 9 禁止清单（返工都是从这里来的）

1. 8 格宽大头、整格眼 —— 那是吉祥物；兵用 4 格头 + slab 眼。
2. 浮点坐标、非整格 —— 一格 0.7 个格子的东西不存在。
3. 平滑权重、手动画权重、手动挪点。
4. 贴图、UV、图集、每个材质一套颜色（同一材质内部靠顶点色分档）。
5. 用 mesh decimate 出 LOD。
6. 事后补套筒（基准里没预埋就只能重做基准）。
7. 静止帧带骨缩放。
8. 靠整体缩放（`slim`、`scale`）拉开体型差 —— 必须改格数。
9. 队色超过两道横线，或队色占比 >9%。
10. 改了基准却不在 §10 登记。
